# Ручной запуск задач (offline / Windows / без планировщика)

> В этой ветке нет планировщика (launchd на macOS, cron на Linux, Task Scheduler на Windows).
> Всё, что в оригинальном IWE крутилось по расписанию, здесь запускается **руками** из git bash.
> Установщики расписания (`roles/*/install.sh`, `setup/optional/setup-cloud-scheduler.sh`,
> `scripts/setup-extractor-feeders.sh`) отключены заглушкой и просто отсылают сюда.

## Что раньше шло по расписанию

| Задача | Скрипт | Когда шла по расписанию | Зачем |
|--------|--------|--------------------------|-------|
| Утренний Стратег | `roles/strategist/scripts/strategist.sh` | каждое утро (Hour/Minute) | сбор данных за вчера, заготовка плана дня |
| Недельное ревью | `roles/strategist/scripts/strategist.sh` | раз в неделю | заготовка недельного ревью |
| Проверка inbox (Экстрактор) | `roles/extractor/scripts/extractor.sh` | по интервалу (StartInterval) | разбор входящих заметок |
| Центральный диспетчер | `roles/synchronizer/scripts/scheduler.sh` | 00:00 / 03:00 / утро | запуск дочерних задач, бэкапы, отчёты |
| Помодоро-напоминания | `setup/optional/pomodoro-alert.py` | по интервалу | напоминания о перерывах |

## Как запускать вручную

Открой git bash в корне рабочего каталога и запускай по необходимости:

```bash
# Утренняя заготовка плана дня (раньше — по расписанию утром)
bash roles/strategist/scripts/strategist.sh

# Разбор входящих заметок
bash roles/extractor/scripts/extractor.sh

# Дневной прогон диспетчера (бэкапы, отчёты, дочерние задачи)
bash roles/synchronizer/scripts/scheduler.sh
```

### Что из этого нужно, если день открываешь через `/day-open`

- **Обычный день** — ничего: утренний Стратег в такие дни собирает план дня, то же делает `/day-open`.
- **День стратегирования** (`strategy_day` в `day-rhythm-config.yaml`, по умолчанию понедельник) —
  до сессии подготовь черновик плана недели, его ждёт короткая еженедельная сессия:
  ```bash
  bash roles/strategist/scripts/strategist.sh session-prep
  ```
- **Недельный отчёт** (`WeekReport`) — по желанию, в конце недели:
  ```bash
  bash roles/strategist/scripts/strategist.sh week-review
  ```

Роли сами берут `qwen`, если он установлен (правило A12 ветки), с ключами, которые Qwen
понимает. Другая программа или модель — через переменные: `AI_CLI=/путь/к/программе`,
`AI_CLI_EXTRA_FLAGS="--model имя-модели --allowedTools Read,Write,Edit,Glob,Grep,Bash"`.

> Перед первым запуском один раз выполни `bash setup-offline.sh` —
> он подставит пути в шаблонные плейсхолдеры `{{...}}`.

## Что НЕ работает offline (и не нужно запускать)

- **Облачная телеметрия** (`.qwen/hooks/agent-trace-uploader.sh`, `scripts/iwe-trace.py`) —
  отправка в облако невозможна; локальные трейсы пишутся на диск и сохраняются.
- **Telegram-уведомления** (`scripts/fmt-critical-alert.sh`) — нет сети.
- **Google Calendar / News** (`scripts/server-calendar.sh`, `scripts/server-news.sh`) —
  отключены заглушкой, day-open работает без них.
- **MCP-серверы** (`.mcp.json`) — пусто, облачные знания недоступны offline.
- **Авто-обновление** (`update.sh`) — обновление только через скачивание ZIP-архива ветки
  (инструкция внутри `update.sh`).
- **Подтяжка репозиториев при первом касании** (`.qwen/hooks/pull-on-touch.sh`) — в
  `.qwen/settings.json` не подключена: без удалённого репозитория и сети каждая попытка
  ждала бы таймаута.
- **Проверка доставки недельного ревью** (`roles/strategist/scripts/strategist.sh`, с v0.41) —
  стратег сверяет, что отчёт появился на удалённом `origin/main`. Без удалённого репозитория
  проверить нельзя, и запуск помечается `FAILED`, даже если `WeekReport` создан. Сам файл
  смотрите в `current/` своего пространства.
- **Обновление по расписанию утреннего плана** (`seed/strategy/scripts/day-open-pipeline.sh`
  и его помощники с Telegram) — ни одна роль его не запускает и в шаблоне; offline не нужно.
- **Гейт открытия сессии перед коммитом** (`.qwen/hooks/session-open-gate.sh`, с v0.41.9) — не
  подключён. Он пропускает `git commit`/`git push`, только если сессия открыта через
  `scripts/session-guard.sh`. Этот скрипт записывает номер сессии только для Claude Code, а в
  git bash на Windows вообще не запускается (нужен WSL2). Подключённый гейт заблокировал бы
  каждый коммит. Привязку работы к РП держите по протоколу открытия, как раньше.
- **Обновление служебных скриптов в вашем пространстве** (`update-derived-snapshot.py`,
  `generate-executor-catalog.py` в `DS-strategy/scripts/`, с v0.41.9) — `update.sh` этой ветки в
  пространство не пишет, скрипты остаются в версии дня установки. Открытие дня берёт свою копию
  из папки шаблона, поэтому сейчас это ни на что не влияет.

## Запрет интернета для IWE и Qwen Code

Без этих настроек Qwen Code по умолчанию отправляет статистику использования в облако Alibaba и
вместе с ней адрес вашей модели из `baseUrl` (даже при выключенной телеметрии), при каждом старте
запрашивает каталог моделей `models.dev` и проверяет обновления. Прокси здесь не используется:
каждый выход выключен своим переключателем.

**Что доставляет `update.sh` само** (файл `.qwen/settings.json`): отключены статистика, проверка
обновлений, фоновый сбор пакетных результатов, окно отзывов, интеграция с IDE, веб-поиск; в
`permissions.deny` добавлены `WebFetch` и `WebSearch`. Хук конца сессии
(`.qwen/hooks/session-end-status.sh`) заглушён: он писал статус агента в базу Neon.

**Что делается один раз руками.** Настройки проекта Qwen читает только из папки запуска, а запрос к
`models.dev` настройками не выключается вовсе, поэтому добавьте в `C:\Users\<имя>\.qwen\.env` три строки
(файл создайте, если его нет; ключи API, которые там уже лежат, не трогайте), затем перезапустите Qwen:

```
QWEN_USAGE_STATISTICS_ENABLED=0
QWEN_CODE_MODELS_DEV=off
QWEN_CODE_DISABLE_PRECONNECT=1
```

Этот файл действует при запуске Qwen из любой папки, `update.sh` его не трогает. Скрипты ветки его не
пишут и не печатают.

**Проверка** (только читает, значений из `.env` не показывает):

```
bash scripts/iwe-offline-check.sh
```

Повторяйте после каждого обновления самого Qwen Code: новые версии могут добавлять новые обращения в
сеть, а выключено только то, что перечислено выше. Затем сверьтесь по трафику: запустите Qwen, сделайте
один обмен с моделью и посмотрите `netstat -ano | findstr ESTABLISHED` для процессов `node` (список PID:
`tasklist | findstr /i node`); должен остаться только адрес модели.

**Остаётся открытым (переключателями не закрыто):** MCP-серверы и расширения, если вы их настроили;
команды, которые модель запускает в shell (`curl`, `npm`, `git`); `git fetch`/`push` из ручных ролей, если
в хранилище есть `origin`; Telegram из ручных ролей, если есть `~/.config/aist/env`; `ssh` у
`scripts/iwe-grep-secret.sh` при заданных хостах. Жёстко закрыл бы только брандмауэр Windows (нужны права
администратора). Если понадобится страховка поверх переключателей, добавляется отдельной фазой
(например, прокси-переменные), сейчас её нет намеренно.

**Известное расхождение:** Qwen Code не читает `.qwen/settings.local.json`, который сеет эта ветка, поэтому
его `permissions` не действуют; пока не исправлено.

## Защита базы принципов при работе создателя паков

Хук `.qwen/hooks/pack-creator-spf-guard.sh` подключён (через ту же прослойку, что ниже), но
**фактически не защищает**: он включается только при `PACK_CREATOR_ACTIVE=1`, а эту переменную
никто не выставляет (так и в шаблоне). Вдобавок на путях Windows вида `C:\…` хук правку не
распознаёт даже при включённой переменной. Не полагайтесь на него: правки в `SPF/` и `FPF/`
во время `/pack-creator` проверяйте глазами.

## После сжатия контекста

После `/compress` хук `.qwen/hooks/precompact-restore.sh` возвращает агенту слепок последних
реплик, снятый перед сжатием. После **автоматического** сжатия Qwen запускает хук без ожидания,
поэтому слепок может появиться в контексте на ход позже.

## Восстановление памяти из бэкапа

`bash scripts/restore-from-exocortex.sh` ищет каталог памяти Qwen той же формулой, что
`scripts/link-memory.sh`, и связывает `memory/` через него: симлинк → соединение каталогов
(`mklink /J`, **права администратора не нужны**) → копия. Если после восстановления
`memory/` оказалась копией, а не ссылкой, — запустите `bash scripts/link-memory.sh --force`.

## Защита от утечки секретов: нужны jq и python3

Хуки `secret-leak-block`, `secret-file-read-block`, `secret-mcp-dump-guard` не дают агенту
прочитать или вывести секреты (`.env`, ключи, выгрузки токенов через MCP). Им нужны
**`jq`** и **`python3`**. В git bash на Windows `jq` по умолчанию нет — положите
`jq.exe` в каталог из `PATH` (например `~/bin`, его добавляет `setup-offline.sh`);
`python3` даёт обёртка из `setup-offline.sh` [4e].

Если зависимости нет, защита **выключается** (иначе хук блокировал бы каждую команду
агента, включая ту, что нужна для починки) и агент видит предупреждение
«Защита … выключена» при каждом вызове. Это сигнал поставить `jq`, а не игнорировать.

Хуки подключены через `.qwen/hooks/qwen-tool-name-shim.sh`: Qwen Code передаёт хуку имя
инструмента `run_shell_command`/`read_file`/…, а хуки шаблона ждут имён Claude
(`Bash`/`Read`/…). Без прослойки защита блокировала бы все вызовы.

## Версионирование

Локальный git без удалённого репозитория. Фиксируй прогресс обычными коммитами:

```bash
git add <конкретные-файлы>
git commit -m "..."
git log --oneline      # история для отката
```
