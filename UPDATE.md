# Обновление ветки `qwen-windows-offline` из upstream

> **⚠ Это инструкция для МЕЙНТЕЙНЕРА форка** — как пересобрать саму ветку из свежего
> upstream. Если ты конечный пользователь и хочешь обновить свою установку на рабочей
> машине — тебе сюда **не надо**: см. `README.md` → раздел «Обновление установленной
> версии» (скачать ZIP → заменить папку FMT → `bash update.sh`).

## Идея

Эта ветка — **детерминированная адаптация** main: ~95% отличий это механика
(переименование `CLAUDE.md`→`QWEN.md`, `.claude/`→`.qwen/`, строковые замены) плюс
небольшой набор «наших» файлов. Поэтому обновляемся **не через `git merge`**
(он давал бы конфликты на каждом апдейте), а через **регенерацию**: берём свежий
main и заново прогоняем `scripts/adapt-to-qwen-offline.sh`.

```
upstream → fork/main (как сейчас) → [adapt-to-qwen-offline.sh] → qwen-windows-offline
```

## Шаги

### 1. Обновить `main` из upstream (как сейчас)

Так же, как форк делал это раньше (коммиты «chore: update from upstream template vX.Y.Z»).
Например через апстримный `update.sh` на main, либо вручную. Итог: `origin/main`
содержит новую версию шаблона.

### 2. Регенерировать ветку из свежего main

```bash
git fetch origin

# свежая рабочая ветка от обновлённого main
git checkout -B qwen-next origin/main

# взять адаптер из текущей qwen-ветки (на main его нет) и запустить
git show origin/qwen-windows-offline:scripts/adapt-to-qwen-offline.sh > /tmp/adapt.sh
bash /tmp/adapt.sh --src origin/qwen-windows-offline

# проверить результат
git status
git diff --stat
```

Адаптер (7 шагов):
1. переименует `CLAUDE.md`/`.claude` → `QWEN.md`/`.qwen` (+ seed/skeleton);
2. прогонит строковые замены (URL-safe);
3. восстановит «наши» файлы дословно из старой ветки (`git show`);
4. вставит guard'ы «нет планировщика» (идемпотентно, по маркеру), плюс отдельные
   формулировки для `agent-trace-uploader.sh` и `setup-local-gateway.sh` (правило A10),
   и проверит правило A11 — что защита пользовательских файлов в `setup/build-runtime.sh`
   на месте (проверка, кода не вставляет);
5. перенесёт блоки README/QWEN между маркерами;
6. прогонит Windows/offline нормализацию — правила A3–A6 (пути через `$IWE_SCRIPTS`,
   `export IWE_WORKSPACE` в bootstrap, offline-пометка `gh`, `update.sh --check` вне daily);
7. покажет **детектор дрейфа**: какие апстрим-коммиты пришли в «наши» файлы после SHA,
   записанного в `.qwen/owned-baseline.tsv`. Шаг 3 восстанавливает эти файлы дословно,
   поэтому апстрим-правки в них теряются молча — детектор единственное место, где это видно.

> **Шаг 7 нельзя пропускать.** Именно так был потерян хук `memory-exocortex-sync`:
> подключён в шаблоне с v0.35.4, до ветки не доехал ни за одну из трёх регенераций.
> Разобрал апстрим-правку (перенёс или осознанно отказался) → поставь текущий SHA main
> в `.qwen/owned-baseline.tsv`, иначе файл останется в отчёте навсегда.

### 3. Зафиксировать и опубликовать

```bash
# Стейджить ТОЛЬКО явными путями. `git add -A` / `git add .` / `git add -u` запрещены:
# они подхватывают изменения других агентов, работающих в репозитории параллельно,
# и приписывают их этому коммиту. Список путей берётся из `git status --short`.
git add <путь> <путь> ...
git diff --cached --name-only     # сверить, что застейджено ровно то, что нужно
git commit -m "regen qwen-windows-offline from main vX.Y.Z"

# обновить ветку (история линейная — force; ветка генерируемая)
git branch -f qwen-windows-offline qwen-next
git checkout qwen-windows-offline
git push --force-with-lease origin qwen-windows-offline
git branch -D qwen-next
```

> `--force-with-lease` безопаснее `--force`: откажет, если кто-то успел запушить.
> Ветка регенерируемая, поэтому force здесь — норма, а не риск (история = main + детерминированный transform).

## Что является «source of truth»

- **Механика** (переименования/замены) — в самом адаптере. Меняешь правило →
  правишь адаптер, не 130 файлов руками.
- **Наши файлы** — их редактируешь прямо в ветке; адаптер восстанавливает их дословно.
  Полный список — переменные `OWNED`/`OWNED_FILES` в самом адаптере, они же source of
  truth; на сегодня это 14 файлов: `.qwen/settings.json`, `.mcp.json`, `update.sh`,
  `.gitattributes`, `.gitignore`, `setup-offline.sh`, `scripts/link-memory.sh`,
  `setup/install-iwe-paths.sh`, `MANUAL-JOBS.md`, `MIGRATION.md`, `UPDATE.md`,
  `scripts/adapt-to-qwen-offline.sh`, `.qwen/owned-baseline.tsv`,
  `update-manifest.local.json`.
  Добавляешь новый «наш» файл → впиши его в **оба** списка адаптера, а если у файла есть
  соответствие в шаблоне — заведи строку в `.qwen/owned-baseline.tsv`, иначе он попадёт
  в отчёт шага 7 как несверенный.
- **Вставные блоки** README/QWEN — между маркерами `QWEN-OFFLINE:*`; редактируешь
  в ветке, адаптер переносит.

## Если upstream сломал «наш» файл

Например upstream сильно переписал `setup/install-iwe-paths.sh` (он у нас в
OWNED — восстанавливается дословно, апстрим-правки потеряются). После регенерации
сделай diff против main и реши, нужно ли перенести апстрим-изменения в наш файл:

```bash
git diff origin/main -- setup/install-iwe-paths.sh
```

Аналогично для guard'ованных скриптов (`roles/*/install.sh` и т.п.) — там апстрим-
правки СОХРАНЯЮТСЯ (берётся свежий файл + вставляется только guard-блок).

## Проверка после регенерации

Механическая часть:

```bash
find . -name '*.sh' -not -path './.git/*' -exec bash -n {} \;   # синтаксис по ВСЕМ скриптам дерева
python3 -c "import json;json.load(open('.qwen/settings.json'));json.load(open('.mcp.json'))"
grep -rn 'CLAUDE_PROJECT_DIR' --include='*.sh' --include='*.json' . | grep -v CHANGELOG   # должно быть пусто
```

Содержательная часть — то, чего механика не поймает:

- **Отчёт детектора (шаг 7)** — разобрать каждый файл в списке: перенести апстрим-правку
  или осознанно отказаться, затем поднять SHA в `.qwen/owned-baseline.tsv`. Пустой отчёт
  и неразобранный отчёт выглядят одинаково только в глазах того, кто его не открыл.
- **Родитель коммита** — `git log -1 --format=%P` должен совпадать с SHA целевого релиза
  main. В цикле 4 ветка собралась от предыдущей версии, потому что коммит релиза
  существовал только локально и не был запушен; проверка родителя ловит это за секунду.
- **README не потерял таблицу отличий** — строка «Было (Claude Code)» на месте. Повторный
  прогон адаптера по уже адаптированному дереву её портит (шаг 2 применяет замены второй раз).
- **`git diff main -- setup/build-runtime.sh`** — должны быть только ветковые замены
  `.claude` → `.qwen`. Если в файле пропала функция `is_protected_user_file`, шаг 4 скажет
  об этом сам (правило A11): собирать ветку в таком виде нельзя — установка затрёт
  пользовательские настройки.

> **Адаптер не идемпотентен.** Запускать только на свежем дереве от `origin/main`.
> На уже адаптированном дереве шаг 2 применяет строковые замены повторно (портит README),
> а шаг 3 восстанавливает «наши» файлы из опубликованной ветки — затирая правки, которые
> ты только что внёс. Точечную правку вноси редактированием файла и коммитом, не прогоном
> адаптера.
